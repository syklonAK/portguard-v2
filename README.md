# 🛡️ PortGuard

**مدیریت‌گر پورت و ریورس‌پروکسی — همه‌چیز در یک باینری، مخصوص سرورهای اوبونتو**

PortGuard یک ابزار تحت وب، سبک و تک‌فایلی است که روی سرور اوبونتوی شما اجرا می‌شود و سه کار اصلی انجام می‌دهد:

1. **تشخیص** — همه‌ی پورت‌های در حال سرویس‌دهی سرور را اسکن می‌کند، می‌گوید هر پورت متعلق به کدام پروسه است و کدام پورت‌ها «مدیریت‌نشده» هستند.
2. **مدیریت** — مپینگ پورت‌ها (دامنه/پورت ← بک‌اند) را از طریق یک رابط وب حرفه‌ای مدیریت می‌کند و کانفیگ **Nginx** یا **HAProxy** را تولید و امن اعمال می‌کند.
3. **مانیتورینگ** — سلامت هر بک‌اند را لحظه‌ای چک می‌کند و CPU/RAM/دیسک سرور را در داشبورد نشان می‌دهد.

## ✨ ویژگی‌ها

### 🔍 تشخیص پورت و سرویس
- اسکن سوکت‌های Listen روی TCP/UDP با دستور `ss` (در نبود آن، تجزیه‌ی مستقیم `/proc`)
- نمایش **نام پروسه، PID، کاربر** به‌ازای هر پورت
- **کلاس‌بندی خودکار سرویس‌ها**: وب‌سرور، لودبالانسر، SSH، xray/v2ray، دیتابیس، DNS، داکر و…
- مارک‌کردن پورت‌های **مدیریت‌نشده** (پورت‌هایی که هیچ مپینگی پوشش‌شان نمی‌دهد) با دکمه‌ی «Map» برای ساخت سریع مپینگ
- اسکن دوره‌ی خودکار + اسکن دستی

### 🔀 مپینگ پورت‌ها (ریورس‌پروکسی)
- پروتکل‌های **HTTP / HTTPS / TCP / UDP**
- انتخاب موتور برای هر مپینگ: **Nginx یا HAProxy**
- چند بک‌اند با **وزن** و حالت **backup** (لودبالانس داخلی)
- پشتیبانی **WebSocket**، **HTTP/2**، ریدایرکت 301 و هدرهای سفارشی
- **Host Header** اختصاصی برای هر مپینگ (ریلی به نود خارجی)
- **مسیریابی پویا بر اساس Path** برای ترنسپورت‌های **ws / httpupgrade / xhttp** — الگوی `/<prefix>/<port>` که پورت مقصد را از خود path استخراج می‌کند (مخصوص Xray و v2ray): با یک دامنه و یک پورت TLS، همه‌ی اینباند‌ها سرویس می‌شوند
- **سایت فیک ضد DPI**: مسیرهای ناشناخته به‌جای 404 یک وب‌سایت واقعی‌نما (آماده یا HTML دلخواه) سرو می‌کنند
- **تانل Hedioum**: مدیریت سمت ایرانِ تانل (رلی‌های raw/tls، بریج xray dokodemo→SOCKS5 با اعتبارسنجی/بکاپ/rollback)
- **مدیریت چند سرور با ایجنت بی‌سر (v2.5)**: پنل اصلی سرورهای جدید را با **یک تک‌خط** راه می‌اندازد — خودِ باینری و اسکریپت نصب را سرو می‌کند تا یک اوبونتوی تازه در چند ثانیه نودِ کاملاً مدیریت‌شده شود (مپینگ، گواهی، ابزار، Apply و نمای لایو، همه از راه دور). دیگه لازم نیست روی نود پنل نصب کنید!
- **لاگ لایو اتصالات**: همه‌ی اتصال‌های ورودی (IP، پورت مقصد، پروسه، مدت) به‌صورت زنده با دسته‌بندی managed/unmanaged و Top Talkers — نمای امنیتی
- **آپدیتر داخلی**: با یک کلیک از Settings آخرین نسخه را بیلد و سرویس را ری‌استارت می‌کند — بدون نصب مجدد
- **محدودیت پهنای باند Per-UUID (v2.6)**: سینک کاربران از پنل پاسارگارد، پروفایل‌های پهنای باند (Basic/Premium/…) و اعمال سقف دانلود/آپلود هر کاربر Xray روی نودها با Linux tc — incremental و با audit کامل. جزئیات فنی: [docs/BANDWIDTH.md](docs/BANDWIDTH.md)
- **تولید آزاد کانفیگ**: هر مپینگ علاوه بر فرم بصری، با ویرایشگر **JSON خام** قابل ساخت است
- تشخیص **تداخل پورت‌ها** قبل از ذخیره (داخل همان موتور، بین دو موتور و با پورت خودِ پنل)
- امکان ساخت مپینگ فقط برای ریدایرکت (بدون بک‌اند)

📖 راهنمای کامل همه‌ی قابلیت‌ها: [docs/USAGE.md](docs/USAGE.md)

### 🛡️ اعمال امن کانفیگ (بدون قطعی!)
هر بار روی «Apply» می‌زنید این چرخه اجرا می‌شود:

```
رندر کانفیگ در پوشه موقت
   ↓
اعتبارسنجی:  nginx -t  /  haproxy -c
   ↓ (در صورت خطا: هیچ فایلی دست نمی‌خورد)
بکاپ خودکار با timestamp  →  /var/lib/portguard/backups/<زمان>/
   ↓
نوشتن اتمیک (rename) فایل‌ها
   ↓
reload صفر-قطعی (اگر سرویس خاموش بود: start)
   ↓ (در صورت خطای reload: بازگردانی خودکار بکاپ + reload مجدد)
ثبت در Audit Log
```

> **کانفیگ نامعتبر هرگز به سرویس زنده نمی‌رسد.** اگر nginx به هر دلیلی نتواند reload شود، خودکار به کانفیگ قبلی برمی‌گردید.

### 🔐 گواهی SSL
- آپلود جفت PEM (فول‌چین + کلید خصوصی)
- تولید **Self-Signed** با SAN کامل و مدت دلخواه
- فایل‌های `.crt/.key` برای nginx و فایل ترکیبی `.pem` برای HAProxy **خودکار** تولید می‌شوند
- نمایش روزهای باقی‌مانده اعتبار هر گواهی با رنگ‌بندی هشدار

### 📊 مانیتورینگ و داشبورد
- چک دوره‌ای TCP + HTTP هر بک‌اند با اندازه‌گیری **latency** و شمارش خطاهای متوالی
- به‌روزرسانی زنده از طریق **SSE**
- داشبورد CPU / RAM / دیسک / Load / Uptime
- صفحه‌ی Monitoring جداگانه برای وضعیت هر target

### 👤 امنیت
- **ویزارد راه‌اندازی اولیه**: اولین بازدید، حساب ادمین ساخته می‌شود
- ورود با **JWT** (HS256، کلید تصادفی ذخیره‌شده در دیتابیس) و هش **bcrypt**
- محدودیت تلاش ورود ناموفق (۵ بار در دقیقه per-IP)
- **Audit Log کامل**: چه کسی، کِی، چه کاری — با وضعیت موفق/خطا
- مجوز فایل کلید خصوصی گواهی‌ها `0600`

## 🚀 نصب

### پیش‌نیازها
- اوبونتو 20.04 / 22.04 / 24.04 (سایر دبی‌بیس‌ها هم احتمالاً کار می‌کند)
- دسترسی root
- اینترنت برای دانلود Go و پکیج‌ها

### نصب با یک فرمان (تک‌خطی)

```bash
sudo bash -c "$(curl -fsSL https://raw.githubusercontent.com/syklonAK/portguard-v2/main/deploy/remote-install.sh)"
```

این فرمان به‌صورت خودکار مخزن را در `/opt/portguard` کلون/به‌روزرسانی می‌کند و نصب کامل را اجرا می‌کند.

> پورت پنل را می‌توانید با متغیر `PORTGUARD_PORT` عوض کنید:
> ```bash
> sudo PORTGUARD_PORT=9000 bash -c "$(curl -fsSL https://raw.githubusercontent.com/syklonAK/portguard-v2/main/deploy/remote-install.sh)"
> ```

### نصب روی سرور (از سورس موجود)

```bash
sudo bash /opt/portguard/deploy/install.sh
```

### نصب یکجای Fleet با Ansible

```bash
cd portguard/ansible
# inventory/hosts.ini را ویرایش کنید: یک [portguard_master] + [portguard_nodes]
ansible-playbook site.yml --limit portguard_master            # نصب پنل
ansible-playbook site.yml --limit portguard_nodes \
  -e portguard_agent_token=...                                # دیپلوی همه agent ها
ansible-playbook service.yml -e portguard_service_target=apply \
  -e portguard_api_user=admin -e portguard_api_pass=...       # اعمال کانفیگ از طریق API
```

راهنمای کامل: [ansible/README.md](ansible/README.md)

### افزودن نود مدیریت‌شده (بدون نصب پنل روی نود!)

```
            ┌────────────────────┐
            │   پنل مستر (شما)   │
            │   MASTER:8080      │
            └─────────┬──────────┘
                      │ ① توکن + تک‌خط تولید می‌شود (Servers → Deploy new node)
                      ▼
        ┌─────────────────────────────┐
        │  سرور جدید (اوبونتو 22/24)  │
        │  ② paste تک‌خط نصب           │
        │  → دانلود باینری مستر        │
        │  → سرویس portguard-agent     │
        │  → پورت 8081 باز می‌شود      │
        └─────────┬───────────────────┘
                  │ ③ Servers → Add server (همان توکن)
                  ▼
        مپینگ‌ها، گواهی‌ها، ابزارها، Apply و نمای لایو — همه از مستر
```

1. در پنل اصلی: **Servers → Deploy new node** — توکن و تک‌خط مربوطه تولید می‌شود.
2. روی سرور اوبونتوی جدید، تک‌خط را اجرا کنید:

```bash
sudo bash -c "$(curl -fsSL http://MASTER:8080/api/agent-install.sh)" -- -master http://MASTER:8080 -token TOKEN -role generic
```

   - برای سرورهای تانل، نقش را ست کنید: `-role iran` یا `-role foreign`
   - پورت agent با `-port` قابل تغییر است (پیش‌فرض 8081)

3. در پنل اصلی: **Servers → Add server** با همان توکن و پورت 8081.

نود به‌صورت `portguard agent` اجرا می‌شود — سرویس بی‌سر که فقط node API توکن‌دار را سرو می‌کند. مستر مپینگ‌های آن را می‌سازد (دکمه **Manage**)، گواهی آپلود می‌کند، ابزارها (xray، hedioum، certbot و…) را نصب می‌کند، خط لوله امن Apply را از راه دور اجرا می‌کند و نمای لایو آن را می‌خواند. نسخه‌ی مستر و نودها همیشه یکی است (نودها باینری خودِ مستر را دانلود می‌کنند).

**نکات:**
- فایروال نود باید پورت 8081 را فقط برای IP مستر باز کند (اسکریپت خودش ufw را باز می‌کند)
- توکن قابل چرخش است: Servers → کارت نود → Edit → توکن جدید
- حذف نود: `systemctl disable --now portguard-agent && rm -rf /opt/portguard-agent /etc/systemd/system/portguard-agent.service`
اسکریپت نصب به‌صورت خودکار:
1. **Nginx** و **HAProxy** و `libnginx-mod-stream` را نصب می‌کند (و site پیش‌فرض را خنثی می‌کند تا با سرویس‌های موجود تداخل نکند)
2. در نبود Go، آخرین نسخه را نصب می‌کند
3. باینری را می‌سازد (فرانت از قبل داخل مخزن build شده — نیازی به Node نیست)
4. سرویس **systemd** را می‌سازد و فعال می‌کند (`portguard.service`)

سپس مرورگر را باز کنید:

```
http://<IP-سرور>:8080
```

اولین بازدید، ویزارد ساخت حساب ادمین را نشان می‌دهد. 🎉

> پورت پنل را می‌توانید با متغیر `PORTGUARD_PORT` عوض کنید: `PORTGUARD_PORT=9000 sudo -E bash deploy/install.sh`

### حذف (Uninstall)

```bash
# حذف پنل (دیتا و nginx/haproxy نگه داشته می‌شوند)
sudo bash -c "$(curl -fsSL https://raw.githubusercontent.com/syklonAK/portguard-v2/main/deploy/uninstall.sh)"

# حذف کامل همراه با دیتا (ادمین، مپینگ‌ها، گواهی‌ها، بکاپ‌ها)
sudo bash -c "$(curl -fsSL https://raw.githubusercontent.com/syklonAK/portguard-v2/main/deploy/uninstall.sh)" -- --purge-data --yes

# حذف خیلی کامل: حتی nginx و haproxy هم پاک شوند
sudo bash -c "$(curl -fsSL https://raw.githubusercontent.com/syklonAK/portguard-v2/main/deploy/uninstall.sh)" -- --purge-data --purge-packages --yes
```

از سورس موجود: `sudo bash /opt/portguard/deploy/uninstall.sh [--purge-data] [--purge-packages] [--yes]`

### بیلد از سورس

```bash
make web      # بیلد داشبورد React (نیازمند Node 20+)
make linux    # باینری لینوکس amd64 (فرانت داخل باینری embed می‌شود)

```

خروجی نهایی فقط **یک فایل** است: `bin/portguard` — فرانتاند داخلش embed شده.

## 📖 راهنمای استفاده

### داشبورد (Dashboard)
نمای کلی: مصرف منابع (به‌روزرسانی هر ۵ ثانیه)، خلاصه‌ی پورت‌ها، تعداد مپینگ‌ها و وضعیت سلامت بک‌اندها.

### پورت‌ها (Ports)
جدول همه‌ی سوکت‌های Listen با فیلتر «All / Unmanaged / Managed» و جستجو. دکمه **Scan now** اسکن فوری می‌زند. ردیف‌های نارنجی «unmanaged» پورت‌هایی هستند که هیچ مپینگی پوشش‌شان نمی‌دهد — دکمه‌ی **Map** کنار هر کدام، فرم ساخت مپینگ را با همان پورت از پیش پر می‌کند.

### مپینگ‌ها (Mappings)
- **New mapping**: نام، موتور (nginx/haproxy)، پروتکل، IP و پورت Listen، دامنه‌ها، گواهی SSL (برای https)، بک‌اندها، WebSocket و…
- تغییرات اول فقط در دیتابیس ذخیره می‌شوند؛ با دکمه‌ی **Apply** کانفیگ واقعی تولید و اعمال می‌شود و سرویس‌ها reload می‌شوند.
- دکمه‌ی **Validate** فقط اعتبارسنجی می‌کند (بدون دست زدن به سرویس‌ها) — برای تست قبل از اعمال.
- کلید **Enabled** هر ردیف مپینگ را موقتاً خاموش/روشن می‌کند.

> **توجه:** مپینگی که پورت 80 یا 443 را بگیرد، اگر آن پورت‌ها الان در اشغال سرویس دیگری (مثلاً xray) باشد، موقع Apply با خطای bind مواجه می‌شود — در این حالت خودکار rollback می‌شود و سرویس قبلی دست‌نخورده می‌ماند.

### گواهی‌ها (SSL Certs)
آپلود PEM یا تولید Self-Signed. گواهی فقط وقتی قابل حذف است که هیچ مپینگی از آن استفاده نکند.

### مانیتورینگ (Monitoring)
وضعیت زنده‌ی هر target به‌تفکیک مپینگ: up/down، latency، تعداد خطای متوالی و زمان آخرین چک (رفرش خودکار هر ۱۰ ثانیه).

### لاگ رخدادها (Audit Log)
همه‌ی رخدادهای مهم: ورود، ساخت/ویرایش/حذف مپینگ، Applyها (موفق و ناموفق)، تغییرات گواهی و تنظیمات.

### تنظیمات (Settings)
- مسیر فایل‌ها: `nginx.conf`، `haproxy.cfg`، باینری‌ها، پوشه‌ی گواهی‌ها و بکاپ‌ها
- بازه‌ی چک سلامت (حداقل ۵ ثانیه) و بازه‌ی اسکن پورت (حداقل ۳۰ ثانیه)
- **Auto-Apply**: بعد از هر تغییر مپینگ، خودکار Apply شود (پیش‌فرض: خاموش)
- تغییر رمز عبور

## 🏗️ معماری

```
portguard/
├── cmd/server/main.go      ← نقطه ورود: لود کانفیگ، استارت حلقه‌ها، HTTP server
├── internal/
│   ├── api/                ← روتر chi، میدل‌ور JWT، Broker خود SSE، هندلرها
│   ├── service/            ← ارکستراسیون Apply: رندر→validate→بکاپ→اتمیک→reload→rollback
│   ├── proxy/              ← اینترفیس Engine + رندرکننده‌های nginx و haproxy
│   ├── scanner/            ← اسکن پورت (ss → fallback /proc) + کلاس‌بندی سرویس
│   ├── health/             ← حلقه چک سلامت TCP/HTTP
│   ├── store/              ← SQLite (modernc بدون CGO) + مایگریشن + کوئری‌ها
│   └── sysinfo/            ← آمار سیستم با gopsutil
├── web/                    ← داشبورد React 19 + Vite + Tailwind (با go:embed داخل باینری)
└── deploy/                 ← install.sh + portguard.service
```

**جریان داده:** مرورگر (React) ← REST/JWT + SSE ← پنل Go ← نوشتن کانفیگ + systemctl ← Nginx / HAProxy

**دیتابیس:** SQLite (فایل واحد در `/var/lib/portguard/portguard.db`) — بدون هیچ وابستگی خارجی.

## 🔧 عیب‌یابی

| مشکل | راه‌حل |
|---|---|
| پنل بالا نمی‌آید | `systemctl status portguard` و `journalctl -u portguard -n 50` |
| Apply خطای validate می‌دهد | پیام خطا خروجی واقعی `nginx -t`/`haproxy -c` است؛ مپینگ مشکل‌دار را اصلاح کنید |
| Apply خطای bind می‌دهد | پورت Listen در اشغال سرویس دیگری است (از صفحه Ports ببینید چه پروسه‌ای) — rollback خودکار شده، نگران نباشید |
| مرورگر باز نمی‌شود | فایروال: `ufw allow 8080/tcp` (در صورت فعال بودن ufw) |
| فراموشی رمز ادمین | `systemctl stop portguard && rm /var/lib/portguard/portguard.db && systemctl start portguard` (ریست کامل — مپینگ‌ها هم پاک می‌شوند!) |
| کانفیگ خراب دستی | بکاپ‌ها در `/var/lib/portguard/backups/<زمان>/` — کافیست فایل‌ها را برگردانید و `systemctl restart nginx haproxy` |

## 📝 نکات امنیتی

- پنل باید با root اجرا شود (نوشتن `/etc/nginx`، `/etc/haproxy` و reload سرویس‌ها نیاز دارد). پورت 8080 را ترجیحاً با فایروال به IPهای مورد اعتماد محدود کنید.
- ورود با رمز SSH را پس از نصب، به کلید تبدیل کنید.
- کلیدهای خصوصی گواهی‌ها با مجوز `0600` در `/var/lib/portguard/certs` نگه‌داری می‌شوند.
